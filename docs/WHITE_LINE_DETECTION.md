# 흰색 선 후보 검출 및 후속 분류 기준

> 2026-11-17 기준. 현재 구현과 후속 계획을 구분한다. 현장 사용자 확인 전 차선·차로 수를 확정하지 않는다.

## 1. 현재 실행 순서

1. 원본 WGC PNG를 변경하지 않고 정지선 분석 ROI를 확인한다.
2. 원본에서 흰색 Hough 선분을 검출해 `W#` 후보로 기록(`white_marking_candidates_raw`).
3. 검은 도면 좌측 상단 고정 UI 문자 영역의 흰색 픽셀만 제외한다(`ui_text_exclusion`); 이후 후보도 별도 보존(`white_marking_candidates_after_ui`).
4. 기존 노면화살표 `A#` 후보(초록 테두리·회색 바탕·내부 흰색)를 찾는다. A# 전체 회전 사각형과 초록색 테두리 경계 3px을 검색 마스크에서 추가 제외한다.
5. 남은 흰색 픽셀에서 `W#` 후보를 다시 검출(`white_marking_candidates`); 이 결과만 현재 근거 이미지에 그린다.
6. 검출 전후의 후보 수, 제외된 픽셀 수, 좌표를 사람이 비교한다. `W#`는 선 조각 후보 번호이지 실제 차선 수가 아니다.

## 2. 현재 적용 기준

| 항목 | 값 | 확정 상태 |
|---|---|---|
| HSV 흰색 | H 0~179 / S 0~65 / V 185~255 | 현재 설정값 |
| 최소 Hough 선분 길이 | 8px | 현장 후보 탐지용 |
| Hough 투표 임계값 | 5 | 현장 후보 탐지용 |
| Hough 연결 허용 공백 | 4px | 현장 후보 탐지용 |
| 수평/수직/대각선 | 모두 허용 | 분류 전 단계 |
| 연속 흰색 점유율 | 제한 없음 | 분류 전 단계 |
| 선분 그룹화 | 수행하지 않음 | 현장 재설계 대상 |
| 고정 UI 문자 제외 | 픽셀 사각형 2개, 흰색만 제외 | 위치 고정 가정 |
| 노면화살표 제외 | A# 초록 테두리 검증 회전 사각형 전체 + 경계 3px | 후보 기반 임시 제외 |

색상과 UI 영역 좌표는 `map_validator/analysis/input_tool/color_ranges.json`에서 변경 가능하다. 20px 실선 판정, 74% 점유율, 실선/점선 두 단계 분류는 **현재 W 단계에는 적용되지 않는다**.

## 3. 후속 분류안 (미구현)

- 원시 W에서 문자·노면화살표 등 명확한 비차선 오브젝트를 **순서대로 별도 마스크**로 제외하되, 이전 단계 결과를 보존한다.
- 남은 흰색 선분을 기울기·투영 겹침·축방향 공백·서로 다른 평행선 분리 기준으로 분석해 **실선 L**, **점선 D**, **미분류 W**로 구분한다.
- 실제 점선은 공백이 반복되는 동일 선상의 조각을 하나의 선으로 묶고, 물리적으로 다른 평행선은 서로 합치지 않는다.
- L/D 확정에 사용할 최소 길이·연속성 비율·기울기 허용 오차·공백 길이는 사용자와 현장 결과를 비교한 뒤 결정한다.

## 4. 검수 시 확인할 항목

- 상단 상태 문구의 W 오탐이 없어졌는지, 특히 글자 바로 옆 실제 차선을 잘못 제거하지 않았는지
- A# 초록 테두리와 내부 전체에서 W#가 제거됐는지(인접 차선 일부 누락 허용)
- 제외 전/후 후보 개수 감소가 실제 문자·화살표 제거 때문인지
- 중앙선 C와 정지선 S/G 결과가 이전과 동일한지

※ Windows 현장 검증과 테스트 코드는 아직 수행하지 않았다.

## 2026-11-17 초록 테두리 기준 노면화살표 전체 영역 마스킹

- 기존에는 노면화살표 A# 회전 사각형 내부 **흰색 픽셀만** W# 후보 검출에서 제외했으나, 현장 이미지에서 A1/A2의 W# 조각이 남았다. 사용자가 주변 일부 차선 누락을 허용한 기준을 반영해 **초록 테두리 검증을 통과한 회전 사각형 전체 + 경계 3px**(`color_ranges.json.road_arrow.exclusion_margin_px`)을 후속 W# 검색 마스크로 사용한다.
- 제외 마스크와 교차하는 Hough W 선분은 통째로 제외하여 공백 4px 연결에 의해 A# 영역을 가로지르는 W#가 남지 않도록 한다. 원본 PNG, 빨강 마커, 시안 정지선 S/G, 노란 중앙선 C 및 A# 검출 조건은 유지한다.
- 결과 `checks.road_arrows`에 `excluded_region_pixels`, `excluded_white_pixels`, `mask_margin_px`를 기록하고 A 후보별 `mask_bbox`와 최종 W의 `rejected_mask_overlap_segments`를 기록한다. **원본 W → 고정 UI 문자 제외 후 W → A 영역 제외 후 W** 결과 JSON은 계속 보존한다.
- A#는 확정이 아닌 후보이므로 오검출 시 일부 실제 차선이 마스킹될 수 있다. Windows 현장 실행·테스트는 별도 요청 전 수행하지 않았다.
