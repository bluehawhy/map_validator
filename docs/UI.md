# map_validator Windows 제어 UI

참고 UI: https://github.com/bluehawhy/nv_c_test (PyQt6, 작은 반투명 상단 고정창, 드래그 헤더, 상태·로그 표시).

## 실행 조건 및 설치

Windows 11과 설치된 호환 Python을 사용합니다. 3.11이 꼭 필요하지는 않습니다. Python 런처에서 사용할 수 있는 버전은 `py list`로 확인합니다.

```powershell
git clone https://github.com/bluehawhy/map_validator.git
cd map_validator
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-ui.txt
# AI 분석 시에만 추가 설치
python -m pip install -r requirements-ai.txt
python -m UI
```

`python -m UI` 실행 시에는 PyQt6·pywinauto를 불러오기 전에 메인 스레드 COM 모드를 STA로 지정합니다. 이는 COM 모드 충돌 시 MTA에서 STA로 재시도하는 경고의 원인을 줄이며, 경고 메시지 자체를 숨기지는 않습니다. pywinauto 버전에 따라 명시된 COM 설정을 안내하는 별도 메시지는 나올 수 있습니다.

기존 설치 환경에서 업데이트할 때도 **`python -m pip install -r requirements-ui.txt`를 다시 실행**해 주세요. 입력도구와 로드뷰 모두 `windows-capture>=2.0.1`을 통한 WGC(Windows Graphics Capture)로 촬영합니다.

또는 `UI\run_ui.bat`을 실행합니다. 실행할 때 `config.yaml`에 없는 항목만 `config.example.yaml`에서 추가하고, 기존에 들어 있는 항목과 값은 그대로 유지한 뒤 UI를 엽니다. `config.yaml`이 없으면 예제 설정으로 새로 만듭니다.

## 앱 로그

앱 시작, 창 검색, Polygon/Link 선택, 화면 준비, 캡처, 분석, 오류 및 Python 경고를 다음 구조로 표시·저장합니다.

`로그타입 | 날짜 시간 | 코드파일:줄번호 | 로그 텍스트`

예시 (파일명·줄번호는 실제 발생 위치에 따라 달라집니다):

```text
INFO | 2026-11-04 10:55:40.123 | UI/app.py:563 | 시작: analyze / Polygon 480706169- Link 98
WARNING | 2026-11-04 10:55:40.456 | pywinauto/__init__.py:71 | UserWarning: Apply externally defined coinit_flags: 2
ERROR | 2026-11-04 10:55:40.789 | map_validator/windows.py:142 | 작업 오류: zoom label was not exposed through Windows UI Automation | traceback: ...
```

- UI의 **작업 로그** 영역과 콘솔에서 동일 형식을 확인할 수 있습니다. **로그 복사**는 표시된 로그를 복사하며, **로그 폴더**는 저장된 로그 파일 위치를 엽니다.
- 파일 경로: `logs/map_validator.log` (프로젝트 폴더 기준, Git 추적 제외). 최대 5 MiB마다 순환하며 `map_validator.log.1`~`.3`을 보관합니다.
- 작업 스레드의 로그는 Qt 신호를 거쳐 UI에 표시하므로 스레드에서 위젯을 직접 수정하지 않습니다.
- 오류는 가능한 경우 traceback의 **실제 예외 발생 파일과 줄번호**를 기록합니다. traceback은 한 줄 로그 안에 포함합니다.
- `Apply externally defined coinit_flags: 2`는 외부에서 설정된 STA COM 방식을 pywinauto가 받아들였다는 안내 경고로, 동작 실패 자체를 의미하지 않습니다. 경고는 숨기지 않고 `WARNING`으로 기록합니다.
- 로그에는 검수 ID, 작업 파일 경로 등의 정보가 포함될 수 있으므로 외부 공유 전 확인하세요.

## UI 항목과 작업

- **창 정보 보기**: 대상 설정 오른쪽의 버튼을 누르면 현재 제목이 있는 Windows 창을 모달로 표시합니다. 창 제목 검색·새로고침·전체 목록 복사를 지원합니다. 내부 창이나 패널을 확인하려면 최상위 창(예: `HD_3D Tool`)을 선택한 뒤 **선택 창 내부 보기**를 누르세요. 하위 UI Automation 항목은 필요할 때만 최대 300개까지 조회하며, 대상 프로그램을 활성화하거나 설정 파일에 저장하지 않습니다.
- **입력 프로그램 / 로드뷰 프로그램**: 사용자가 프로그램명을 입력한 뒤 **선택** 버튼을 누르면 목록을 띄우지 않고 일치하는 실행 중인 창을 활성화합니다. `프로그램명 - 워크스페이스명` 형태의 실제 창 제목은 워크스페이스 부분을 제외하고 비교합니다. **입력도구(HD_3D Tool)는 창 위치·크기 변경으로 화면이 흰색이 될 수 있으므로 자동 이동·크기 변경·최소화 해제(복원)를 하지 않습니다.** 최소화되어 있다면 사용자가 직접 복원해야 합니다. 로드뷰는 기존 복원 동작을 유지합니다. map_validator UI는 현재 위치에 유지합니다.
- **검수 ID**: 사용자가 **교차로 선형 검수** 창에서 마우스 **왼쪽 클릭을 완료했을 때만** 선택 ID를 다시 읽습니다. Windows 저수준 마우스 후크가 활성 창 제목을 확인하고 약 200ms 뒤 별도 조회 스레드에서 Polygon/Link를 읽습니다. 클릭이 연달아 발생하면 마지막 클릭 기준으로 한 번 조회하며, **주기적인 UI Automation 조회는 하지 않습니다.** 읽은 ID는 크롬으로 전환해도 유지하고, 값이 바뀌었을 때만 UI를 갱신합니다. 조회에 일시적으로 실패하면 마지막 ID를 유지합니다. 입력도구나 교차로 창을 이동·활성화·복원하지 않으며, Polygon·Link 값은 `config.yaml`에 저장하지 않습니다. Polygon만 선택하면 `Polygon <Polygon ID>`, Link를 선택하면 `Polygon <Polygon ID>- Link <Link ID>` 형식입니다. 예: `Polygon 480706169`, `Polygon 480706169- Link 98`. 클릭 후 실제 갱신 시간은 Windows UI Automation 응답 속도에 따라 더 걸릴 수 있습니다. 키보드만으로 선택을 바꾸는 경우 자동 갱신되지 않습니다.
- **저장 경로**: 스크린샷, 분석 이미지, JSON 결과를 저장할 상위 폴더입니다. 프로젝트 내부 상대 경로나 Windows 절대 경로를 사용할 수 있습니다. **찾기**로 폴더를 선택하거나 경로 입력을 마치면 즉시 `config.yaml`의 `output.directory`에 저장하며 다음 실행에도 유지합니다. 기존 경로는 `config.backups/`에 백업합니다.
- **이동**: 없음 / W 전진 / S 후진 중 하나를 지정하고 횟수를 설정합니다. 좌우 시점 회전은 지원하지 않습니다.
- **화면 준비**: **입력도구의 Zoom은 모든 작업에서 자동 조작하지 않습니다.** 분석 시에는 설정에 따라 로드뷰만 활성화해 `Ctrl+End` 스크롤을 실행할 수 있습니다. 입력도구의 위치·크기를 변경하거나 최소화 해제하지 않습니다. 기존 `config.yaml`의 `preparation.input_zoom` 항목이 남아 있어도 무시됩니다.
- **캡쳐만**: **입력도구(`HD_3D Tool`)와 로드뷰(`NLadybugSv`)를 공용 WGC 캡처 함수로 각각 촬영**하여 별도 PNG로 저장합니다. `PrintWindow`는 어느 창에도 사용하지 않으며 캡처 실패 시에도 대체 방식으로 재시도하지 않습니다. **Zoom·스크롤·W/S 이동·로드뷰 열기·창 활성화를 모두 생략하며, 이동 설정이나 로드뷰 열기 체크 여부와 상관없이 현재 상태 그대로 1회 촬영합니다.** 검수 ID가 비어 있으면 작업 스레드에서 한 번 다시 조회하고, 이미 있으면 마지막으로 확인된 ID를 사용합니다.
- **도로후보 분석**: **폴더 선택 팝업 없이 현재 검수 ID의 기존 스크린샷을 곧바로 AI 분석**합니다. 설정된 `output.directory/<검수 ID>/` 아래의 `*_NLadybugSv.png`, `*_NLadybugSv_01.png` 등 로드뷰 원본 이미지(구버전 `frame_00.png`도 지원)를 검색합니다. 사진이 없으면 **`캡쳐만`을 먼저 실행하라는 오류**를 표시하고, 창을 다시 찍거나 만들지 않습니다. 기존 입력툴 스크린샷은 변경하지 않고 로드뷰 사진에서만 도로 영역 기반 좌우 후보를 분석하며 `analysis.json`과 `*_overlay.png`를 별도 저장합니다. **분석 결과는 확정 판정이 아니며 사람 검수가 필요합니다.** 폴더 열기나 로드뷰 이동·스크롤·Zoom 변경은 수행하지 않습니다. AI 의존성이 없으면 `python -m pip install -r requirements-ai.txt`가 필요하며, 최초 모델 실행 시 다운로드가 발생할 수 있습니다.
- **분석 중지**: 현재 진행 중인 캡처 또는 AI 분석 작업의 중지를 요청합니다. 모델 최초 로딩이나 추론 중에는 중지 요청이 즉시 반영되지 않을 수 있습니다. UI의 세 작업 버튼은 `캡쳐만 | 도로후보 분석 | 분석 중지` 한 줄로 배치합니다.
- **설정 저장**: 입력 프로그램과 로드뷰 프로그램은 입력을 마치면 자동 저장됩니다. 검수 ID는 현재 작업에만 사용하며 `config.yaml`에는 저장하지 않습니다. 저장 경로, 투명도 등은 설정 저장 또는 해당 조작 시 `config.yaml`에 저장됩니다. 기존 `open_button_image` 설정은 CLI 호환을 위해 그대로 유지하되 UI에는 노출하지 않습니다. 이 파일은 Git에서 제외됩니다.
- **투명도**: 상단 슬라이더로 제어창의 투명도를 조절합니다.
- **숨기기**: 상단 숨기기 버튼이나 `Esc`로 창을 최소화합니다.
- **결과 폴더**: 가장 최근에 캡처했거나 분석한 검수 ID의 결과 폴더를 Windows 탐색기에서 엽니다.

UI는 **로드뷰를 자동으로 여는 버튼과 분석 전 자동 열기 체크 옵션을 제공하지 않습니다.** 캡처할 때만 입력 프로그램과 로드뷰가 실행되어 있어야 합니다. **도로후보 분석 버튼은 저장된 사진만 처리하므로 대상 프로그램이 실행 중일 필요가 없습니다.** 사진 폴더를 선택하는 팝업도 나타나지 않습니다. CLI의 별도 `--open-roadview` 옵션과 AI 분석 기능은 변경하지 않습니다.

## 캡처 파일명

검수 ID와 각 프로그램 설정 이름을 조합합니다. `Polygon`과 `Link` 사이의 하이픈 뒤 공백은 파일명에서 제거합니다.

```text
results/Polygon 480706820- Link 142/
  Polygon 480706820-Link 142_HD_3D Tool.png
  Polygon 480706820-Link 142_NLadybugSv.png
  result.json
```

- 연속 이동을 포함해 여러 번 캡처할 경우 `_01`, `_02` 등 번호를 추가하여 이미지가 서로 덮어써지지 않게 합니다.
- 캡처 원본과 `result.json`은 유지합니다. `result.json`의 `frames[].image`, `roadview_image`, `work_image`는 원본 파일을 참조하고, 새로 생성하는 `analysis.json`은 AI 분석 점수·후보 및 `*_overlay.png`를 참조합니다. 분석은 로드뷰 스크린샷만 사용합니다.
- 입력도구와 로드뷰 창은 각각 개별 캡처하며 두 화면을 한 이미지에 합치지 않습니다.
- 두 창 모두 WGC가 유효한 화면을 반환하지 못하면 오류로 기록합니다. `PrintWindow` 폴백은 제공하지 않습니다. 프로그램에 따라 백그라운드 캡처 지원 여부가 다를 수 있습니다.

## 크롬을 사용하는 상태에서 비활성 캡처 확인

1. `NLadybugSv` 로드뷰를 최대화한 다음 **최소화하지 않고** 그대로 둡니다. Windows에서는 창이 크롬 뒤에 가려져 있어도 됩니다.
2. 크롬을 전면에 열고, `map_validator`의 작은 제어 UI만 화면 위에 띄웁니다. 로드뷰를 다시 활성화하지 않습니다.
3. 제어 UI에서 **이동 없음**을 선택하고, 기존에 읽힌 검수 ID가 있는 상태에서 **캡처만**을 누릅니다.
4. 크롬 포커스가 그대로인지, `logs/map_validator.log`에 두 창의 `WGC 비활성 창 캡처 성공` 기록이 있는지 확인합니다.
5. 결과 폴더의 `*_NLadybugSv.png`와 `*_HD_3D Tool.png`가 각각 **실제 로드뷰 영상과 입력도구 화면**인지 확인합니다. 검은 화면·흰 화면·정지 화면은 정상 캡처로 판단하지 않습니다.

이 확인 단계는 화면 캡처만 대상으로 하며 **백그라운드 W/S 이동이나 Zoom/스크롤 지원 여부를 검증하지 않습니다.** Windows Graphics Capture 방식에서도 대상 프로그램의 실제 렌더링 호환성은 Windows 환경에서 확인해야 합니다.

## 검수 방식과 안전

검수자는 업무 프로그램의 2D 선형(하늘색 진입, 파란색 진출, 주황색 교차점 연결)과 로드뷰 캡처를 직접 대조해 좌·우회전 방향의 차로 또는 연결 도로가 보이는지 확인합니다. UI는 검수 결과를 업무 프로그램에 자동 저장하지 않습니다.

UI는 PyQt6의 **별도 캡처·저장사진 AI 분석 작업 스레드**와 **마우스 클릭 감시 스레드**를 사용합니다. 도로후보 분석 버튼은 선택된 검수 ID 폴더의 기존 PNG만 분석하며 창 캡처·조작을 실행하지 않습니다. Windows 저수준 마우스 후크는 클릭이 발생했는지만 판단하고, 실제 Polygon/Link 조회는 별도 STA 스레드에서 수행하여 UI와 마우스 후크를 막지 않습니다. 주기적인 UI Automation 조회는 없으며, 백그라운드 캡처 작업 중에는 클릭 기반 선택 감시를 일시 중지합니다. UI 갱신은 Qt 시그널로 전달하고, UIA를 사용하는 작업 스레드에서 Windows STA COM을 초기화·해제합니다. 종료 시 마우스 후크를 해제하고 조회 스레드에 중단을 요청하되 UI 이벤트 루프를 막지 않습니다. 로드뷰 자체 캡처는 다른 창이나 UI가 앞에 있어도 캡처하도록 시도하며, 화면에 표시된 픽셀을 직접 읽는 방식이 아닙니다. 분석 버튼은 W/S 이동·로드뷰 스크롤·포그라운드 입력을 보내지 않습니다. 입력도구 Zoom 자동 조작도 하지 않습니다. 실제 로드뷰 이동과 연속 캡처를 수행하는 CLI 자동화는 별도 경로에 남아 있으며 UI 버튼과 무관합니다. 자동화 모듈은 Qt 창이 생성된 뒤 불러와 Windows DPI 초기화 충돌을 피합니다. PyAutoGUI FAILSAFE가 활성화되어 있으며, 화면 왼쪽 위로 마우스를 이동하면 제어 작업을 긴급 중단할 수 있습니다. 작업 중 UI를 닫으면 중지 요청과 작업 스레드 종료를 기다립니다.

결과 상태는 `possible`, `not_detected_review_required`, `not_analyzed`이며 모든 결과는 사람의 검수가 필요합니다. 도로 영역 검출은 실제 좌·우회전 차로의 존재나 합법적 회전 가능 여부를 확정할 수 없습니다.

## 알려진 제약

사용자 확인으로 입력도구 WGC 캡처는 정상 동작하지만, **로드뷰 WGC 캡처는 실제 업무 Windows 환경에서 별도 확인이 필요합니다.** 창 제목·버튼 템플릿은 환경에 맞게 설정해야 합니다. 두 프로그램 모두 WGC만 사용하며 프레임이 비어 있거나 캡처에 실패해도 `PrintWindow`로 폴백하지 않습니다. 창을 최소화하거나 Windows 세션이 잠긴 경우 캡처가 실패할 수 있습니다. AI 모델 최초 다운로드에는 네트워크와 저장 공간이 필요할 수 있습니다.
