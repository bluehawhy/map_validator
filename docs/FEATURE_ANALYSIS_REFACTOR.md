# 검수 항목별 분석 및 개별 촬영 설계 (2026-11-16)

## 구현 범위
- 사용자 수동 4단계 WGC 촬영과 기존 `staged_capture.json` / `staged_analysis.json` / `road_scores.csv` 데이터는 유지한다.
- UI를 **단계별 수동 촬영** / **개별 촬영 분석** 두 탭으로 표시한다.
- 개별 촬영은 현재 `input_tool`(HD_3D Tool) 화면 **한 장을 WGC로 촬영**한다. 로드뷰 이동·회전·Zoom·창 상태 변경은 없다.
- 개별 촬영 데이터는 검수 ID별 `captures/individual/input_tool_rNNN.png`와 별도 보고서에 저장한다. 단계별 촬영본과 섞거나 덮어쓰지 않는다.
- `input_tool` / `roadview` 인식 모듈과 `comparison`을 **검수 항목별 코드**로 분리했다. `input_features.py`, `roadview_features.py`는 구호출 호환 진입점이다.
- 고정 `direction_6` 등의 파일을 만들지 않는다. 교차로 도로는 `road_id`, `angle_deg`(측정된 경우), `role`, `checks`, `source_stage` 속성으로 다룬다. 현재 4단계는 임시 레거시 연결이며 **각도나 도로 수의 자동 검출 기능이 아니다**.

## 방향과 검수 항목
- 모든 도로에서 **차로 수·정지선·일반 유도선·컬러유도선**을 검수 대상으로 정의한다.
- 진입 도로는 추가로 **노면 방향 화살표**를 검사한다. 기존 단계별 UI에서 진입 전('before')에 적용한다.
- 도로 유무(`road_exists`)는 기존 진출 단계의 보조 검수 필드로 보존한다.
- `stop_line`은 진입 전 로직만 기존 자동 후보 탐지와 연결되어 있으며 다른 촬영 단계는 인식이 검증되지 않아 `null`을 보존한다.
- 차로 수·노면 화살표·일반 유도선 등 검증되지 않은 항목은 **0/false로 추정하지 않는다**.
- 정지선 / 일반 유도선 / 컬러유도선은 서로 다른 항목과 결과로 유지한다.

## 개별 촬영 분석: 빨간 점 기준
1. 사용자가 직접 `input_tool` 화면을 맞춘 뒤 **개별 촬영 · 정지선 분석** 버튼을 누른다.
2. 현재 열린 입력툴 화면을 WGC로 읽고 원본 PNG를 새 revision으로 보존한다.
3. 이미지의 **검은 도면 영역 중심 부근**에서 현재 사용자 위치를 나타내는 **작은 빨간 사각 표시**를 찾는다. 빨간 도로 선형은 가느다란 선으로 제외하며, 작고 채워진 표식을 후보로 사용한다.
4. 유일한 빨간 위치 표시 후보가 있으면 **이미지 픽셀 좌표**, 도면 중심 좌표 및 편차, 도면 내부 상대 좌표를 기록하고 주변 ROI의 **시안색 직선 후보**를 수집한다. 검수자는 오버레이를 열어 표식 위치·정지선 여부를 직접 확인한다.
5. 표식이 검출되지 않거나 다수의 중심 후보가 구별되지 않으면 `not_found` / `ambiguous`로 기록하고 주변 선 분석을 생략한다. 도면 중앙 좌표를 표식의 실제 검출 결과로 대신하지 않는다.
6. 이 버전의 선 후보는 **정지선 확정 검출이 아니라 현장 검증용 후보**다. 실제 횡단보도, 진행 방향, 도로 경계를 구분한 뒤 확정 규칙을 보완해야 한다.

개별 촬영 출력:
- `<검수 ID>/individual_capture.json`: 현재 및 이전 revision 이미지 참조 이력
- `<검수 ID>/individual_analysis.json`: 최신 빨간 점·선 후보 보고서
- `<검수 ID>/individual_analysis_rNNN.json`: revision별 보존 보고서
- `<검수 ID>/captures/individual/input_tool_rNNN.png`: 원본
- `<검수 ID>/captures/individual/input_tool_rNNN_overlay.png`: 후보 표시 이미지

## 항목별 검증 순서
1. **빨간 점 좌표**: 후보가 실제 기준점인지 사진마다 확인
2. **정지선**: 실제 유무·위치·횡단보도 및 다른 선과 혼동한 사례 확인
3. 차로 수, 노면 화살표, 일반 유도선, 컬러유도선
4. 도로별 연결/매핑, 비정형 교차로 확장

실제 현장 표본 검증이 완료되기 전까지 특정 후보를 자동 승인하지 않는다.

## 호환성
- `before` / `after_left` / `after_straight` / `after_right` 기존 촬영 순서 및 파일명을 유지한다.
- `staged_analysis.json`의 `input_expected` 필드는 유지하고 `input_tool_expected` 별칭 및 `roads` 목록을 추가한다.
- 단계별 오버레이, score_history/ 및 통합 CSV 형식은 변경하지 않는다.
- 입력툴 사진의 빨간 표시는 **현재 사용자 위치를 나타낸다**. 화면 내 픽셀 좌표와 도면 내 상대 좌표는 계산할 수 있지만, **실제 지도 좌표·도로 ID·진행 방향·교차로 중심을 확정하는 근거가 아니다**. 실제 측위 및 비정형 도로 방향 분석은 후속 검증 대상으로 둔다.
- 해당 변경은 현장 Windows, HD_3D Tool 및 NLadybugSv에서의 실행 검증을 포함하지 않는다. 테스트 코드는 요청 없이 추가·실행하지 않는다.

## 2026-11-16 현재 위치 빨간 표시 검출 진단 로그

현장 사진에서 빨간 표시가 존재하는데 `not_found`로 끝나는 문제를 분석하기 위해 **검출 조건은 그대로 유지하고** 각 단계의 로그를 추가했다. `map_validator.analysis.input_tool.red_marker` 로거는 기존 `map_validator` 로그 구성을 사용하므로 GUI 작업 로그 및 `logs/map_validator.log`에서 확인할 수 있다.

- `[현재위치][1/5]`: WGC 입력 이미지 해상도, 도면 검출 범위, 도면 중심, 빨간 표시 탐색 ROI
- `[현재위치][2/5]`: HSV 빨간 픽셀 수, 형태 변환 **이전**의 빨간 연결 객체 수와 중심 근접 객체(최대 8개)의 좌표/크기/면적
- `[현재위치][3/5]`: 3×3 `MORPH_OPEN` 전후 빨간 픽셀 수, 제거량 및 남은 객체 수
- `[현재위치][4/5]`: 크기·가로세로비·채움비율 조건별 탈락 수, 탈락 샘플, 통과 후보
- `[현재위치][5/5]`: 후보 좌표·중심 편차 또는 `not_found`/`ambiguous`와 탈락 원인
- `[개별촬영][위치진단]`: 촬영 버전·정지선 후보 분석 여부·원본/오버레이/분석 이력 파일명

`individual_analysis.json`의 `red_marker.diagnostics`와 개별 촬영 탭 결과에도 주요 숫자를 남긴다. 실패한 경우에도 **이미지 중심을 검출 좌표로 대체하지 않는다**. 이 변경은 위치 표시의 자동 검출률을 개선한 것이 아니라 **어느 규칙 때문에 실패하는지 현장에서 확인하기 위한 진단 도구**다.

현장 확인 순서: **개별 촬영 · 정지선 분석** 한 번 실행 → `로그 복사` 또는 `로그 폴더` 버튼으로 `[현재위치]` 로그 확인 → 근거 오버레이에서 현재 위치를 대조. 실무 원본 이미지·실제 업무 ID/좌표가 공개 저장소로 업로드되지 않도록 주의한다.

## 2026-11-16 현장 보완: 개별 촬영 검수 ID 실패 분리 및 정지선 후보 가시화

**개별 촬영 분석**은 검수 ID가 없는 상태에서도 현재 `input_tool` 화면을 WGC로 촬영·분석한다. Windows UIA/Win32 선택 조회를 기다리지 않는다. ID가 비어 있으면 `<output.directory>/_unassigned_individual/Unassigned_<UTC일시>_<임의ID>/` 아래 **촬영마다 별도의 고유 폴더**를 사용하며, 정식 검수 ID처럼 보이도록 자동 연결하거나 `config.yaml`에 저장하지 않는다. 결과에는 `unassigned: true`와 `case_id_status: "unassigned"`가 표시된다. 이미 확인된 검수 ID가 있으면 기존 `<검수 ID>/` 구조를 유지하며, **단계별 4단계 촬영에서는 검수 ID가 여전히 필수**다.

정지선 후보 표시:
- `local_stop_line.py`에서 Hough 직선 후보를 긴 순서대로 `S1`, `S2` ... 번호로 매기고, 오버레이에 **노란 선·주황 끝점·번호 태그**를 표시한다.
- 원본 `input_tool_rNNN.png`, 전체 근거 `input_tool_rNNN_overlay.png`는 유지한다. 새로 `input_tool_rNNN_focus.png`를 해당 ROI의 확대 미리보기로 보존한다.
- `개별 촬영 분석` 탭에 미리보기를 표시하고, 기존 **근거 이미지 보기**에서 전체 해상도 오버레이를 열 수 있다. 결과 목록과 보고서 `checks.stop_line.line_candidates[].candidate_id`의 번호가 일치한다.
- 선 6개는 **Hough에서 검출된 선 조각 후보 6개**다. 동일한 정지선의 여러 조각일 수 있고 실제 정지선 6개로 확정하지 않는다.
- Win32/UIA 선택 조회가 실패하면 원본 TreeItem 수·선택 수·SysTreeView32 존재와 방문 수 등을 기록한다. 촬영을 위해 창을 활성화하거나 조작하지 않는다.

현장 Windows 검수에서는 이미지 확대 표시, 번호 및 실제 정지선과의 대응, 선택 조회 실패 재현을 별도로 확인해야 한다. 자동 테스트는 요청 없이 실행하지 않는다.
