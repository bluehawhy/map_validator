# 요구사항 및 판정 기준

## 핵심 목적

Windows 업무 프로그램에서 선택한 교차로의 2D 경로선이 로드뷰의 실제 도로와 맞는지 사람이 검수하도록 돕는다. 주요 확인 항목은 **경로에서 기대하는 좌회전·우회전 방향의 차로 또는 연결 도로가 로드뷰에 보이는지**다. 자동화는 캡처와 후보 표시까지만 하며 최종 판정·승인은 사람이 한다.

## 업무 프로그램의 2D 선형

| 색 | 의미 |
|---|---|
| 하늘색 | 원도로 경로(진입) |
| 파란색 | 나가는 도로 경로(진출) |
| 주황색 | 교차점 연결 경로 |

이 선형은 검수자가 기대 방향을 확인할 때 참고한다. 현재 버전에서는 업무 프로그램 화면에서 선형·색상을 자동 추출하거나 좌·우 기대값을 계산하지 않는다.

## 작업 흐름

1. 업무 프로그램에서 교차로를 선택한다.
2. 업무 프로그램 버튼으로 해당 위치의 로드뷰를 연다.
3. 별도 로드뷰 창을 활성화하고 W/S로 앞뒤 이동한다. 이동 횟수는 사용자가 정한다.
4. 각 시점 화면을 캡처하고, 필요하면 도로 영역과 좌·우 후보 오버레이를 만든다.
5. 검수자가 2D 선형의 방향과 캡처를 대조해 좌·우회전 차로 또는 연결 도로가 보이는지 확인한다.
6. 애매한 경우 원본 캡처를 직접 확인하고 판단을 보류한다.

## 포함 및 제외 범위

포함:
- Windows 업무 프로그램과 별도 로드뷰 창 탐색
- 이미지 템플릿을 이용한 로드뷰 열기 버튼 조작
- W/S 앞뒤 이동과 순차 캡처
- 도로 영역 분할 및 좌·우 후보 영역 표시
- 검수 ID별 PNG 및 JSON 보고서 저장

제외:
- 로드뷰의 좌우 회전 및 마우스 시점 조작
- 직진 차로, 차로 수, 노면 화살표, 차선 규제·교통 규칙 검증
- 2D 선형 자동 인식 및 로드뷰와 자동 최종 대조
- 자동 승인, 업무 프로그램에 결과 입력 또는 저장

## 결과 해석

- `possible`: 화면의 해당 쪽에 도로 영역 후보가 있음. 회전 차로의 존재를 증명하지 않는다.
- `not_detected_review_required`: 후보가 검출되지 않음. 해당 차로·도로가 없다고 확정할 수 없다.
- `not_analyzed`: AI 분석 없이 캡처만 수행함.
- `requires_human_review`: 모든 결과에 적용되는 최종 검수 조건.

커브, 원근, 차도 폭 변화, 주차 공간, 그림자, 차량·건물 가림, 촬영 시점 차이로 오탐·미탐이 발생할 수 있다. 결과만으로 도로의 법적 이용 가능성이나 실제 회전 가능 여부를 판정하지 않는다.

## 실행 및 데이터 제약

- 업무 프로그램과 로드뷰 창이 Windows 데스크톱에 표시되어야 한다.
- 키보드 이동은 W/S만 수행하며 화면 회전은 하지 않는다.
- 실무 캡처·좌표·업무 정보·개인 설정·결과물은 공개 저장소에 올리지 않는다.
- 로드뷰 데이터의 캡처와 처리 전에 제공사의 이용 조건을 확인한다.
