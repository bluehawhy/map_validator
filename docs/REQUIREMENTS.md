# 요구사항 및 판정 기준

## 핵심 목적

Windows 업무 프로그램의 2D 선형과 연계된 별도 로드뷰에서 **좌회전/우회전 방향으로 연결되는 골목 도로의 실제 존재 여부**만 1차 검수한다. 사용자가 다시 검수하므로 자동 최종 판정/승인은 하지 않는다.

## 선형 색상

| 색 | 의미 |
|---|---|
| 하늘색 | 원도로 경로(진입) |
| 파란색 | 나가는 도로 경로(진출) |
| 주황색 | 교차점 연결 경로 |

2D 선형은 차로별 폴리라인과 교차로 진·출 연결 폴리라인의 조합. 초기에는 화면에서 이를 자동 추출하지 않으며, 도로 후보 검출만 지원한다.

## 작업 흐름

1. 업무 프로그램에서 교차로를 선택한다.
2. 로드뷰 버튼으로 해당 지점의 로드뷰를 연다.
3. 로드뷰 별도 창에서 W/S로 정해진 횟수만 전후진한다.
4. 각 시점 스크린샷을 저장한다.
5. 좌측/우측의 연결도로 후보를 표시한다.
6. 사람이 2D 경로선과 실제 골목 연결 여부를 대조한다.

## 범위

- 포함: 좌측 골목도로 존재 후보 / 우측 골목도로 존재 후보, W/S 이동, 원본 캡처, JSON 보고서.
- 제외: 직진·차로 수·노면 표시·정지선·차선 규제·화면 회전·최종 승인 또는 수정 자동 입력.

## 보수적인 결과

- `possible`: 좌/우 측면 도로 영역의 *후보*. 존재 확정 아님.
- `not_detected_review_required`: 후보가 안 보임. 도로 없음 확정 아님.
- `not_analyzed`: 캡처만 수행.
- 최종 `requires_human_review`: 모든 경우에 수동 검수.

실제 분기 여부는 고정 카메라 각도, 차량 가림, 원근, 지도/촬영 시점 차이로 불명확할 수 있다.

## 실행 제약과 공개 저장소 보안

- Windows GUI 프로그램과 별도 로드뷰 창이 화면에 나타나 있어야 한다.
- 마우스·키보드는 현장 PC에서 조작된다. 좌우 시점 회전 없음.
- 실무 로드뷰 이미지/좌표/고객 데이터, 개인 설정, 결과 파일은 GitHub에 업로드하지 않는다.
- 캡처 및 모델 활용은 제공사의 이용 조건을 확인한다.
